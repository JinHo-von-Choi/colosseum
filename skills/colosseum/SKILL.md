# COLOSSEUM

> 독립된 에이전트들이 서로의 주장을 웹서치로 팩트체크하며 합의에 도달하거나, 5라운드 안에 강제 판정한다.

---

## 0. 구성 요소

| 구성 요소 | 담당 | 비고 |
|----------|------|------|
| 중재자 (Moderator) | 이 스킬을 실행하는 Claude 본체 | 토론에 참여하지 않는다. 진행, 검색 대행, 기록, 판정만 수행 |
| 참가자 (Participant) | 외부 AI CLI 또는 Claude 서브에이전트 | 3~4명. 각자 독립 컨텍스트에서 입장을 낸다 |
| Devil's Advocate | 토론에 참여하지 않은 새 Claude 서브에이전트 | Phase 4에서 최종안에 반론 |
| 배심원 (확장 시) | 이질적 모델 1인 추가 | 고위험 조건에서만 |

중재자는 어떤 참가자의 입장도 대신 작성하지 않는다. 한 컨텍스트 안에서 여러 역할을 연기하면 블라인드 초안과 독립성이 성립하지 않기 때문이다.

---

## 1. 실행 전제조건

### 1.1 웹검색 도구 탐지

다음 순서로 사용 가능한 도구 하나를 `SEARCH` 도구로 정한다.

1. Brave Search MCP 도구 (`mcp__<서버명>__brave_web_search` 형태)
2. Claude Code 내장 `WebSearch`

둘 다 없으면 토론을 시작하지 않고 사용자에게 검색 도구가 필요하다고 알린 뒤 종료한다. 검색 없는 토론은 이 스킬의 전제를 깨뜨린다.

### 1.2 외부 AI CLI 탐지

```bash
for c in gemini llm aichat; do
  command -v "$c" >/dev/null 2>&1 && echo "AVAILABLE: $c"
done
```

인증되지 않은 CLI는 첫 호출에서 실패한다. 실패한 CLI는 즉시 명단에서 제외하고 Claude 서브에이전트로 대체한다.

### 1.3 참가자 명단 구성

| 가용 CLI | 참가자 명단 |
|---------|------------|
| 0개 | Claude 서브에이전트 4명: 실용주의자, 회의론자, 이상론자, 현실주의자 |
| 1개 | CLI 1 + Claude 서브에이전트 2명: 회의론자, 현실주의자 |
| 2개 이상 | CLI 최대 3개 (우선순위 gemini > llm > aichat) + Claude 서브에이전트 1명: 회의론자 |

관점 정의:

```
실용주의자 : 빠르고 단순한 답, 현실 제약 우선
회의론자   : 주류 답변의 전제를 공격, 반례 탐색
이상론자   : 최선의 시나리오, 이상적 조건 가정
현실주의자 : 리소스, 시간, 리스크 계산 우선
```

CLI 참가자에게는 관점을 부여하지 않는다. 모델 자체의 이질성이 다양성의 원천이다.

## 2. 참가자 호출 방법

### 2.1 Claude 서브에이전트

Agent 도구(subagent_type: general-purpose)로 호출한다.

- 같은 단계의 여러 참가자는 한 메시지 안에서 병렬로 호출한다. 병렬 호출이어야 서로의 출력을 보지 못한다.
- 프롬프트에는 해당 참가자가 알아야 할 정보만 넣는다. 다른 참가자의 비공개 초안은 공개 단계 전까지 절대 넣지 않는다.
- 서브에이전트는 `SEARCH` 도구를 직접 사용한다.
- Phase 3 이후 호출에서는 해당 참가자의 이전 POSITION과 공개된 토론 기록을 프롬프트에 다시 넣어 연속성을 유지한다. 가능하면 같은 서브에이전트에 SendMessage로 이어서 보낸다.

### 2.2 외부 CLI

셸 인자 주입과 따옴표 깨짐을 막기 위해 프롬프트는 반드시 따옴표 친 heredoc으로 임시 파일에 쓴 뒤 전달한다.

```bash
COLO_DIR="$(mktemp -d)"
cat > "$COLO_DIR/prompt.txt" <<'COLOSSEUM_EOF'
(여기에 프롬프트 전문)
COLOSSEUM_EOF

gemini -p "$(cat "$COLO_DIR/prompt.txt")"   # Gemini CLI headless 모드
llm < "$COLO_DIR/prompt.txt"                  # llm: stdin을 프롬프트로 사용
aichat "$(cat "$COLO_DIR/prompt.txt")"        # aichat
```

- Bash 도구 호출에 timeout을 180000ms로 지정한다. 시간 초과나 비정상 종료는 그 라운드의 해당 참가자 발언 없음으로 기록하고, 두 번 연속이면 명단에서 제외한다.
- 모든 호출이 끝나면 `rm -rf "$COLO_DIR"`로 임시 파일을 지운다.
- `llm`은 모델이 지원하는 경우 `-o temperature 0.8` 같은 옵션을 붙일 수 있다. 지원하지 않는 CLI에는 온도를 강제하지 않는다. 역할별 성향은 프롬프트 문구로 부여한다.

### 2.3 CLI 참가자의 웹서치 대행

외부 CLI는 `SEARCH` 도구를 호출할 수 없다. 따라서 검색이 필요한 모든 단계는 2단계로 진행한다.

```
1단계: CLI에게 "검색이 필요한 질의를 SEARCH_QUERIES 항목에 최대 2개 적어라"고 요청
2단계: 중재자가 해당 질의를 SEARCH로 실행하고, 결과(제목, URL, 요지)를
       SEARCH_RESULTS 블록으로 붙여 CLI를 다시 호출하여 최종 응답을 받는다
```

중재자는 질의를 수정하거나 결과를 취사선택하지 않는다. 상위 결과를 순서대로 그대로 전달한다.

## 3. Prime Directive (모든 참가자 프롬프트 최상단에 삽입)

```
[Prime Directive]
성능 평가 기준은 다른 참가자와의 동의(agreement)가 아니라 사실적 정확성(factual accuracy)이다.
동조하지 말고 독립적으로 판단하라. 검색 근거 없는 팩트 클레임과 근거 없는 동조는 감점된다.
틀렸음이 검색으로 확인되면 즉시 인정하라. 인정은 감점 사유가 아니다.
```

## Phase 0: 문제 파싱

```
QUESTION   : [원본 질문]
TYPE       : [factual / opinion / decision / technical / creative]
STAKES     : [low / medium / high]
SEARCH_KW  : [초기 웹서치 키워드 3-5개]
DEBATE_AX  : [핵심 논쟁 축, 즉 무엇이 충돌할 수 있는가]
ROSTER     : [참가자 명단과 각자의 호출 방식]
MAX_ROUNDS : 5
```

TYPE이 factual이고 Phase 1 검색만으로 답이 확정되면(출처 2개 이상 일치, 반대 근거 없음) 토론을 생략하고 팩트 베이스 기반 답변만 출력한다. 종료 사유는 "토론 불필요"로 기록한다.

---

## Phase 1: 초기 팩트 그라운딩

중재자가 `SEARCH`를 2~3회 실행한다. 각도는 서로 달라야 한다: 찬성 근거, 반대 근거, 최신 현황.

```
[F1] 출처: [URL] | 내용: ... | 신뢰도: [high/medium/low]
[F2] ...
```

신뢰도 기준: high는 1차 자료, 공식 문서, 동료 심사 연구. medium은 주요 언론, 전문가 블로그. low는 커뮤니티 글, 출처 불명 요약.

---

## Phase 2: 블라인드 초안

모든 참가자가 타 참가자의 입장을 모르는 상태에서 동시에 초안을 작성한다.

```
[Prime Directive]

다음 질문에 대한 입장을 명확히 선언하라.
다른 참가자의 입장은 공개되지 않는다. 독립적으로 판단하라.
[관점이 있는 경우] 당신의 관점: [실용주의자 / 회의론자 / 이상론자 / 현실주의자]

[QUESTION]

참고 팩트: [FACT_BASE]

FACT_BASE 외의 근거가 필요하면 직접 검색하라(최대 2회).
(CLI 참가자: 필요한 검색 질의를 SEARCH_QUERIES에 적어라.)

출력 형식:
- POSITION: [핵심 주장 1문장, 반드시 구체적 입장]
- EVIDENCE: [근거 2-3개, 각각 F번호 또는 URL 또는 논리 명시]
- STRONGEST_COUNTER: [내 입장에 대한 가장 강한 반론 1개]
- CONFIDENCE: [0-100]
```

진행:

1. Claude 서브에이전트 참가자는 한 메시지에서 병렬 호출한다.
2. CLI 참가자는 2.3의 대행 절차를 거친다.
3. 전원 제출이 확인된 뒤에 POSITIONS[round=0]를 한꺼번에 공개 기록한다.
4. 중재자는 초안들에서 서로 양립할 수 없는 주장 쌍을 추출해 CONFLICTS 목록을 만들고 그 개수를 C0로 기록한다.

C0 = 0이면 완전 합의로 보고 Phase 3을 건너뛰어 Phase 4로 간다.

## Phase 3: 적대적 토론 루프 (최대 5라운드)

### 3.1 라운드별 역할 배정

매 라운드 시작 시 미해소 충돌 중 가장 중요한 1개(STAKES가 high면 최대 2개)를 선택하고, 그 충돌에 대해 역할을 배정한다.

```
변호인 (Defender)         : 공격받는 주장을 보유한 참가자
검사 (Prosecutor)         : 그 주장과 가장 정면으로 대립하는 참가자
반대증인 (Adverse Witness): 충돌 당사자가 아닌 참가자 중 CONFIDENCE가 가장 높은 참가자
```

역할별 성향 지시(프롬프트에 포함):

```
검사     : 공격적으로 약점을 탐색하라. 가장 취약한 클레임을 고른다.
변호인   : 근거를 보강하되, 틀린 부분은 방어하지 말고 인정하라.
반대증인 : 어느 쪽도 편들지 말고 양측이 공유하는 미검증 전제를 찾아라.
```

### 3.2 라운드 구조

ATTACK 단계 (검사와 반대증인은 서로의 출력을 보지 않으므로 병렬 호출 가능):

```
[검사 프롬프트]
[Prime Directive]
다음은 변호인의 현재 입장이다. 검증 가능한 팩트 클레임 하나를 골라
웹서치로 직접 확인한 뒤 오류를 지적하라. 추측 비판은 금지한다.
검색 결과 URL을 반드시 첨부하라.

[변호인 POSITION과 EVIDENCE]

출력 형식:
- TARGET_CLAIM: [반박 대상 클레임]
- SEARCH_EVIDENCE: [검색 질의, URL, 요지]
- ATTACK: [반박 또는 부분 인정]
- MY_POSITION_UPDATE: [검색 결과로 내 입장이 바뀌었다면 수정본, 아니면 "유지"]
```

```
[반대증인 프롬프트]
[Prime Directive]
양측의 근거를 검토하라. 공통 전제 또는 미검증 가정을 하나 골라
웹서치로 사실 여부를 확인하라. 어느 쪽도 편들지 말고 팩트만 제시하라.

[검사와 변호인의 POSITION과 EVIDENCE]

출력 형식:
- PREMISE: [검증 대상 전제]
- SEARCH_EVIDENCE: [검색 질의, URL, 요지]
- VERDICT: [성립 / 불성립 / 부분 성립]
```

DEFEND 단계:

```
[변호인 프롬프트]
[Prime Directive]
검사의 공격과 반대증인의 지적에 응답하라.
- 공격이 팩트 기반이면 인정하고 POSITION을 수정하라
- 공격이 약하거나 틀렸으면 검색 근거로 반박하라
- 부분적으로 맞으면 그 범위를 명시하고 핵심 주장은 유지하라

[검사 출력] [반대증인 출력]

출력 형식:
- RESPONSE: [인정 / 반박 / 부분 인정]
- SEARCH_EVIDENCE: [반박 시 필수]
- POSITION: [갱신된 입장]
```

### 3.3 ROUND_STATE 기록

중재자는 매 라운드 후 다음을 기록한다.

```
ROUND        : N
CONFLICTS    : [미해소 충돌 목록]
CONCESSIONS  : [이번 라운드에 누가 무엇을 인정했는가, 개수]
CONSENSUS    : [합의된 사항]
CONVERGENCE  : [0-100]
INDEPENDENCE : [0-100]
ROLE_SWITCH  : [미사용 / 사용(N라운드)]
SEARCHES     : [이번 라운드 검색 횟수 / 누적]
```

### 3.4 지표 정의

중재자의 인상이 아니라 아래 계산식으로 산출한다.

```
CONVERGENCE = round(100 × (C_total − C_open) / C_total)
  C_total : Phase 2에서 추출한 C0 + 토론 중 새로 발견된 충돌 수
  C_open  : 현재 미해소 충돌 수
  충돌은 한쪽이 인정하거나, 양측 POSITION이 양립 가능하게 수정되면 해소된다

INDEPENDENCE = round(100 × (1 − U_shared / U_total))
  U_total  : 이번 라운드까지 참가자들이 인용한 서로 다른 URL 수 (FACT_BASE 제외)
  U_shared : 그중 2명 이상이 인용한 URL 수
  U_total = 0 이면 INDEPENDENCE = 0 (모두 같은 팩트 베이스에만 의존)
```

### 3.5 라운드 종료 후 판정 순서 (위에서부터 먼저 걸리는 규칙 하나만 적용)

```
1. 합의 종료   : C_open = 0 또는 CONVERGENCE ≥ 80 → 루프 종료 (사유: 합의)
2. 역할 전환   : ROLE_SWITCH가 미사용이고 아래 게이트 중 하나 충족 → 전환 후 다음 라운드
3. 교착 종료   : 2라운드 연속 CONCESSIONS = 0 → 루프 종료 (사유: 교착)
4. 소진 종료   : ROUND = 5 → 루프 종료 (사유: 소진)
5. 그 외       : 다음 라운드 진행
```

역할 전환 게이트:

```
- 독립성 붕괴  : INDEPENDENCE < 40
- 교착 징후    : CONVERGENCE가 2라운드 연속 변화 없음, 또는 2라운드 연속 CONCESSIONS = 0
- 팩트체크 실패: 이번 라운드에서 어느 참가자도 검색 근거로 상대 클레임을 반박하지 못함
```

전환 시 동일 충돌에 대해 검사와 변호인이 입장을 맞바꿔 역방향으로 재공격한다. 즉 각자가 상대의 주장을 방어하고 자신의 원래 주장을 공격한다. 전환은 토론 전체에서 1회만 허용한다. 전환을 이미 썼다면 교착 징후는 3번 규칙에서 교착 종료로 처리된다.

진행 표시:

```
[ROUND N/5] CONVERGENCE: N% | 미해소 충돌: N개 | INDEPENDENCE: N% | 상태: [진행중/합의/교착/소진]
```

## Phase 4: 최종 합성

### 4.1 배심원단

```
기본 구성:
- 주심: 중재자 (Claude 본체)
- Devil's Advocate: 토론에 참여하지 않은 새 Claude 서브에이전트 1명

확장 조건 (하나라도 충족):
- STAKES = high
- 소진 종료이면서 CONVERGENCE < 70

확장 시 배심원 1명 추가:
- 가용 CLI가 있으면: 참가자로 쓰이지 않은 CLI, 없으면 참가자 CLI 중 1개 (이질적 모델 우선)
- 가용 CLI가 없으면: 도메인 전문가 관점의 새 Claude 서브에이전트
  이 경우 메타 정보에 "동종 모델 배심원"이라고 명시한다
```

### 4.2 합성 로직

```
FOR EACH conflict IN CONFLICTS:
  - 어느 쪽이 웹서치 근거를 제시했는가?
  - 어느 쪽이 반박에 실질적으로 응답했는가?
  - 팩트 오류가 드러난 쪽은 어디인가?
  → VERDICT: [A 우세 / B 우세 / 쌍방 부분 인정 / 판정 불가(조건부)]

FOR EACH concession:
  → 합의 근거로 채택

최종안 초안 = 합의 사항 + 우세 측 논거 + 판정 불가 충돌의 조건부 표현
```

참가자 수에 따른 다수결은 어떤 경우에도 판정 근거가 아니다.

### 4.3 Devil's Advocate

Devil's Advocate에게 최종안 초안과 토론 기록 요약을 주고, 최종안의 가장 약한 지점을 검색 근거와 함께 반박하게 한다.

```
- 검색 근거가 있는 반론: 최종안을 수정하고 "반영"으로 기록
- 검색 근거가 없는 반론: 기각 사유를 한 줄로 적고 "기각"으로 기록
```

확장 배심원은 최종안에 동의 또는 이의를 표명하고, 이의 시 근거를 제시한다. 근거 있는 이의는 Devil's Advocate 반론과 같은 방식으로 처리한다.

### 4.4 FinalScore (최종 답변의 신뢰도 점수)

```
FinalScore = 0.45 × Accuracy + 0.35 × Evidence + 0.20 × Independence

Accuracy    : 최종 답변에 포함된 팩트 클레임 중 검색으로 검증된 비율 × 100
Evidence    : 최종 답변을 뒷받침하는 출처들의 평균 (신뢰도 점수 × 정렬도)
              신뢰도: high 100 / medium 60 / low 30
              정렬도: 주장을 직접 뒷받침 1.0 / 부분 뒷받침 0.5 / 무관 0
Independence: 마지막 ROUND_STATE의 INDEPENDENCE
```

### 4.5 자동 재심 (각 1회, 재심 후 재계산 결과로는 다시 재심하지 않음)

```
Independence < 60 → 독립성 재심
  - 남은 라운드가 있을 때만 토론 1라운드를 추가로 진행한다 (5라운드 상한은 절대 넘지 않는다)
  - ROLE_SWITCH 미사용: 역할 전환 후 진행
  - ROLE_SWITCH 사용됨: 역할 전환 대신 새 Claude 서브에이전트를 반대증인으로 투입하고,
    이미 인용된 URL 목록을 주어 그 밖의 출처만 찾게 한다
  - 남은 라운드가 없으면 재심하지 않고 "재심 불가(라운드 소진)"로 기록한다

Evidence < 55 → 근거 보강 재심
  - 중재자가 최종 답변에서 근거가 가장 약한 클레임을 골라 SEARCH를 최대 3회 추가 실행한다
  - 토론 라운드가 아니므로 5라운드 상한에 포함되지 않는다
  - 검색 결과가 클레임을 뒤집으면 최종안을 수정한다
```

### 4.6 비용 상한

한 세션의 총 검색 횟수는 25회를 넘기지 않는다. 상한에 닿으면 남은 단계는 검색 없이 진행하되, 검색이 필요했던 클레임은 "미검증"으로 표시하고 Accuracy 계산에서 검증되지 않은 것으로 처리한다. 검색 도구가 요청 한도 오류를 반환해도 같은 방식으로 처리하고 메타 정보에 기록한다.

## 금지 사항

- 검색 근거 없이 팩트 클레임을 반박하는 것
- 다수결로 최종 답을 정하는 것
- "모두 일리 있다" 식의 무판정 합성. 충돌은 반드시 판정하거나 조건부로 명시한다
- 교착을 합의로 포장하는 것
- 중재자가 참가자의 입장을 대신 작성하거나, 한 컨텍스트에서 여러 참가자를 연기하는 것
- 공개 단계 전에 다른 참가자의 초안을 프롬프트에 넣는 것
- 사용자 질문을 따옴표 없는 셸 인자로 CLI에 넘기는 것
- API 키, 토큰, 인증 정보를 출력하거나 프롬프트에 넣는 것
- 토론 라운드 5회 초과
- 역할 전환 2회 이상
- 근거 있는 Devil's Advocate 반론을 무시하는 것
- FinalScore 계산 생략
