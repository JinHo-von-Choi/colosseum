# 동작 원리

## 단계

| 단계 | 하는 일 |
|------|--------|
| 0. 계획 | 질문 유형, 중요도, 기준 시점을 정하고 명단을 짠다 |
| 1. 사실 기반 | 찬성, 반대, 최신 현황 세 방향으로 검색하고 핵심 사실을 URL, 인용과 함께 남긴다 |
| 2. 블라인드 초안 | 참가자마다 서로를 보지 않고 입장, URL과 인용이 붙은 주장, 핵심 가정, 쟁점, 확률을 쓴다 |
| 2a. 기준선 | 계열 가중 투표와 풀링 확률 `P0` |
| 2b. 쟁점 지도 | 결론을 가르는 충돌 주장 쌍을 고른다. 가치 판단의 차이는 토론 대신 조건부 답으로 보낸다 |
| 3. 라운드 | 쟁점마다 검사가 공격하고, 반대증인이 양측이 공유한 가정을 확인하고, 변호인이 답한다. 기본 1라운드, 최대 3라운드 |
| 4. 판정 | 두 순서로 묻는 배심원, 판정 엔진, 역전 규칙, 사전부검, 점검표, 보고서 |

쟁점이 해소되거나, 새 검증 근거로 바뀐 입장이 하나도 없는 라운드가 나오면 일찍 끝낸다.

## 참가자 규칙

- 참가자는 서로를 익명 라벨로만 본다. 모델 이름과 확률은 공개하지 않는다.
- 검사는 공격 전에 변호인의 주장을 세 문장 이내로 공정하게 다시 쓴다. 변호인이 왜곡이라고 하면 그 공격은 무효다.
- 입장은 검증된 근거나 이름을 댈 수 있는 논리 오류가 있을 때만 바꿀 수 있다. 다른 변경은 `CONFORMITY_FLIP`으로 기록하고 세지 않는다.
- 모델 계열이 하나뿐인데 초안이 모두 같으면, 토론을 생략하기 전에 반대자가 가장 강한 반대 근거를 찾는다.

## 인용 대조

인용마다 그 URL을 가져와 페이지 원문과 비교한다.

- 표시 차이만 무시한다: 공백, 유니코드 호환 문자, 따옴표 모양, 대시와 마이너스 기호, 대소문자, Markdown 표기
- 부호, 숫자, 단위, 부정어, 비교 표현은 그대로 비교한다
- 원문 그대로라도 같은 문장에 인용이 빼먹은 조건("if", "unless", "only", "except", "경우", "-면")이 있으면 `n`이다
- 페이지를 가져오지 못하면, 실제로 돌아온 검색 스니펫에 인용이 글자 그대로 있을 때만 스니펫 수준으로 인정한다

지지 판정은 따로 한다. 이 인용이 문맥까지 고려해 이 주장을 완전히, 일부만, 전혀 뒷받침하지 않는지, 판단할 수 없는지(`full`, `partial`, `none`, `unknown`)를 본다.

## 근거 가중치

근거는 인용이 `v`나 `snippet`이고, 지지 판정이 `full`이나 `partial`이고, 출처가 대체되지 않았을 때만 인정한다. 가중치는 네 요소를 곱한 값이다.

| 요소 | 값 |
|------|----|
| 출처 신뢰도 | high 0.9, medium 0.6, low 0.3 |
| 인용 대조 | v 1.0, snippet 0.5, n 0, u 0 |
| 지지 판정 | full 1.0, partial 0.5, none 0, unknown 0 |
| 최신성 | fresh 1.0, 시점 무관 1.0, unknown 0.75, stale 0.5, superseded 0 |

같은 기사를 옮긴 사본은 한 번만 센다. 근거를 원출처(같은 보도자료, 논문, 통신 기사)별로 묶고 묶음마다 가장 좋은 근거 하나만 쓴다. 주장의 기본 점수는 사전확률 0.2와 각 묶음을 noisy-OR로 합친다. 그래서 약한 근거가 근거 없음보다 낮게 나오는 일은 없다.

## 판정 엔진

1. 공격은 대상의 기본 점수가 공격자보다 0.15 넘게 높지 않으면 패배(defeat)가 된다. 인정된 근거가 있는 undercut(추론을 겨냥한 공격)은 항상 패배를 만든다. 그런 근거가 없는 undercut은 일반 공격과 같이 다룬다.
2. grounded 의미론으로 모든 주장을 인정, 기각, 미정으로 나눈다. 같은 관계를 여러 번 넣어도 한 번으로 센다.
3. preferred 확장은 미정 충돌에서 서로 모순 없는 입장들을 보여 주며, 조건부 답의 갈래가 된다.
4. 감쇠 DF-QuAD로 주장마다 강도를 계산한다. 강도가 0.5(중요도 높음이면 0.7) 이상이면 `ACCEPTED`다.

충돌마다 판정 하나를 낸다.

| 판정 | 뜻 |
|------|----|
| `A_WINS`, `B_WINS` | 한쪽만 인정 |
| `PARTIAL_BOTH_SURVIVE` | 양쪽 모두 인정 |
| `CONDITIONAL` | 미정이고, 양쪽이 각각 모순 없는 입장에 속한다 |
| `VALUE_CONDITIONAL` | 사실이 아니라 가치의 문제 |
| `LOSER_REFUTED_WINNER_UNPROVEN` | 한쪽은 반박됐고 다른 쪽은 입증되지 않았다 |
| `UNRESOLVED`, `NEITHER_ESTABLISHED` | 판정할 수 없다 |

같은 입력이면 늘 같은 결과가 나오고, 결과에 입력의 해시가 붙는다.

## 역전 규칙

최종 답은 다음 셋이 모두 성립할 때만 투표 기준선과 달라진다.

1. 소수 입장의 핵심 인용이 검증되었다.
2. 다수 입장의 반박이 실패했다.
3. 배심원이 두 제시 순서 모두에서 동의했다. 배심원은 가능하면 다른 모델 계열의 에이전트이고, 없으면 호스트 기본 모델로 새 배심원을 세우고 같은 계열이라고 표시한다.

## 확률

`P0`는 초안 작성자 확률의 로그오즈 평균이며, 모델 계열 하나를 한 사람으로 센다. 입장이 셋 이상이면 다른 입장 작성자의 `1 - p`를 나머지 입장 수로 나눠 쓴다. `P_final`은 역전이 없으면 `P0`와 같다. 둘 다 보정되지 않은 값이다.

## 강제 장치

플러그인으로 설치하면 실행 중에 훅이 다음을 강제한다.

- 실행당 검색 25회, 페이지 가져오기 15회
- 스니펫 수준 검증으로 바뀐 뒤에는 페이지 가져오기 차단
- 블라인드 초안을 쓰는 동안 참가자끼리 메시지 차단
- 형식이 틀린 참가자 응답은 한 번 다시 쓰게 함

실행 관리 스크립트는 허용되지 않은 단계 이동과 추가 라운드를 거부한다.
